01 / REASONING

智能体如何思考、规划与协作行动？

8 篇精读

先从 ReAct 的推理—行动闭环与 Toolformer 的工具学习入门，再看 Reflexion 如何利用失败反馈；RAP 推演后继状态，LATS 将搜索、评估与反思结合。接着读 Voyager 的开放探索、MetaGPT 的结构化协作，最后用 Evolving Orchestration 对照固定流程与学习得到的动态编排。

R1 - ReAct 光想不查容易产生幻觉，光做不想又缺乏规划——把“思考、行动、观察”连成闭环，让智能体边查证事实边调整方向。
R5 - Toolformer 怎样学会什么时候该调用工具？用少量示例让模型在语料中采样调用，执行后按后续文本的预测损失筛选，再做微调。
R2 - Reflexion 做错了重来一遍，为什么还会踩同一个坑？不用更新模型权重，而是把失败原因写成自然语言“错题本”留在记忆里，指导下一轮尝试。
R4 - Reasoning via Planning (RAP) 没法在真实环境里反复试错，怎么办？让大模型同时扮演“推理者”与“内部世界模型”，在脑海中用树搜索推演未来状态与长远回报。
R3 - Language Agent Tree Search (LATS) 一条检索轨迹走偏了，其他尝试还能留着吗？把蒙特卡洛树搜索、模型价值评估和语言反思结合起来，比较多个候选分支。
R18 - Voyager 会说铁镐配方，为什么还不能从空背包做出来？在 Minecraft 中按现场状态自动选任务，照着反馈修改执行程序，再把成功技能存成可检索、可组合的代码。
R19 - MetaGPT 几个角色一起写软件，怎样避免接口各说各话？沿绘图应用追踪五角色的结构化交付、共享消息池与执行反馈，再看单元测试能修好什么、不能保证什么。
R61 - Evolving Orchestration 多智能体协作一定要走完固定流程吗？中央编排器按当前状态选择下一位角色或结束任务，再用质量与成本回报训练路由，比较动态协作的收益与弱模型下的退步。

02 / EVALUATION

一次成功之外，怎样检验真实交互中的表现？

3 篇精读

这一组聚焦通用任务交互与运行可靠性：τ-bench 检验对话、工具调用与业务规则下的任务完成，τ²-bench 加入用户也能操作环境的双控制协作；最后用可靠性研究检查重复运行与条件变化下的表现。记忆、角色与社交的专项评测留在对应主题，与被检验的方法一起读。

R6 - τ-bench 能聊天的客服未必守得住业务红线——让智能体在多轮用户对话、数据库读写与复杂行业规则之间周旋，用 pass^k 看看多次运行是否一致。
R7 - τ²-bench 用户不只提问，还得亲手操作手机配合排障，智能体该怎么引导、怎么同步状态？用“双控制”环境找出多轮协作卡在哪里。
R8 - Science of AI Agent Reliability 为什么平均准确率涨了，智能体到了关键生产场景还是让人不放心？不只看一个均值，从一致性、鲁棒性、可预测性与安全性四个角度看看可靠性。

03 / MEMORY

怎样存下经历，并在需要时找回？

6 篇精读

先看记忆如何组织与使用：HippoRAG 连接跨段证据，Zep 追踪事实的时间变化，A-MEM 维护新旧卡片的关联，ReasoningBank 从成败经历提炼可迁移策略。再用 LongMemEval 检验跨会话记忆，用 PersonaMem 检验动态用户画像能否支持贴合当下的回应，串起“存下什么、怎样找回、是否有用”。

R12 - HippoRAG 两个证据段落都在库里，怎么还会漏掉一段？离线抽取关系并建立图索引，查询时用个性化 PageRank 传播查询信号，再汇总成段落分数。
R13 - Zep 用户的现实情况变了，旧记忆该怎么处理？把情节、语义与社区放进三层动态图谱，再用双时态时间轴（T 与 T′）追踪事实的生效与失效。
R14 - A-MEM 新经历来了，旧经历往往也有了新的意义——借鉴卢曼“卡片盒笔记法”，让新记忆入库时自主连接相关旧卡片，并反过来更新旧卡片的语境描述。
R60 - ReasoningBank 保存旧轨迹，为什么还会重犯旧错？从自判成功与失败的经历中提炼策略，供新任务检索；再用 MATTS 比较多路尝试或顺序复查，让更多计算也改善后续记忆。
R16 - LongMemEval 当对话跨越数百场会话，记忆系统到底卡在“没存好”、“没找准”还是“没读懂”？用五大核心记忆能力评测，看看建库、检索与阅读各环节的得失。
R17 - Know Me, Respond to Me (PersonaMem) 能背出用户的历史设定，就等于懂用户吗？在偏好看起来随时间变化的长期交互里，分清“认出用户画像”与“给出真正贴合当下处境的回应”。

04 / CONTEXT

怎样让长历史与经验进入下一次决策？

2 篇精读

MemGPT 解决有限窗口里保留什么、何时从外存调入或调出；ACE 解决任务反馈怎样变成可增量维护的行为手册。两篇分别管理输入容量与经验内容，重点看每次调用实际送给模型的上下文怎样变化。ReasoningBank 放在记忆组，可与 ACE 对照策略如何提炼、检索与更新。

R11 - MemGPT 历史超过窗口后，怎样留下关键事实并找回旧事？借鉴虚拟内存，让模型用函数调用来管理当前工作区、对话历史和归档存储。
R15 - ACE 一次失败怎样变成下一次可用的经验？让执行、反思与策展各管一件事，只对行为手册做增量更新，保住具体策略，再看看反馈质量与持续适应的真实代价。

05 / WORLD MODELS

学会预测动作后果，怎样帮助行动与交互？

2 篇精读

先读 DreamerV3：从真实经验学习世界模型，在想象中训练策略，再回到环境行动；再读 Genie：从视频学习潜在动作，生成可交互环境。与推理组的 RAP 对照，区分语言模型内推演、学习得到的环境动力学与真实观测，避免把想象成功当成真实成功。

R51 - DreamerV3 空背包怎样走到钻石？沿 Minecraft 案例拆开世界模型、想象轨迹与 Actor–Critic 学习，再核对跨领域固定配方，以及“曾找到钻石”与单局成功率的区别。
R52 - Genie 只看角色移动、不知道玩家按键，怎样学出可操作的世界？沿平台跳跃案例拆开动作瓶颈、视频 tokenizer 与动力学模型，再用 CoinRun 检查动作能否迁移。

06 / SOCIAL SIMULATION & ROLEPLAY

如何扮演角色、与他人协商，并从互动中学习？

7 篇精读

从 Generative Agents 的小镇生活出发，用 CharacterBench 检查个体是否守住角色设定，再用 SOTOPIA 检验双人互动中的目标与关系。随后读 SOTOPIA-π 与 SOTOPIA-Ω 怎样改进协商策略、Agentopia 怎样扩展到长期社会生活。最后用 LLM Generated Persona 检查群体代表性，区分角色可信、社交目标达成与现实人群模拟。

R10 - Generative Agents 怎样让智能体过上真实可信的日常，而不是机械复读角色设定？用记忆流记下经历、用定期反思提炼高阶洞见、用层级规划安排小镇社交。
R22 - CharacterBench 只靠闲聊，怎么发现角色忘记旧事、越过知识边界？围绕设定与历史构造针对性追问，用 CharacterJudge 判分，再核对评分与人类的一致性，以及用于训练的收益。
R20 - SOTOPIA 聊得自然，就能在社交中达成目标吗？从借毯子失败出发，看两个角色在私有目标与信息限制下互动，再用七个维度分开评估目标、关系与行为代价。
R57 - SOTOPIA-π 小模型怎样学会协商，而不只礼貌接话？先模仿专家，再筛选自身互动中的高分角色轨迹做离线微调；对照人工评价，检查自动目标评分是否虚高。
R58 - SOTOPIA-Ω 专家也会陷入客气却无进展的僵局。按当前进展与未来预期切换原生回应、换位提示和四步协商，在数据生成时改善策略，再检查目标收益、表达多样性与人工评分差距。
R21 - Agentopia 一次体育馆偶遇，怎样走到第六周的协作？沿周循环与私有记忆拆开长期社会模拟，再看年度奖励如何筛选相对自身进步的轨迹用于离线微调，以及社交收益背后的生活代价。
R55 - LLM Generated Persona 人物档案写得像真人，组成的人群就能代表现实吗？分开检验档案生成与回答模拟，对照选举和问卷数据，看更多细节为什么反而可能带来更大偏移。
