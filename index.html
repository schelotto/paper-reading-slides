01 / REASONING

智能体如何思考、规划与协作行动？

9 篇精读

先从 ReAct 的推理—行动闭环、Reflexion 的语言反思与 Toolformer 的工具学习入门；再看 RAP 与 LATS 如何把树搜索和世界模型引入长程规划。接着读 MetaGPT 的多智能体 SOP 分工与 Evolving Orchestration 的动态编排，最后进入 Voyager 的开放世界技能库与 Cradle 的通用屏幕键鼠控制。

R1 - ReAct 光想不查容易产生幻觉，光做不想又缺乏规划——把“思考、行动、观察”连成闭环，让智能体边查证事实边调整方向。
R2 - Reflexion 做错了重来一遍，为什么还会踩同一个坑？不用更新模型权重，而是把失败原因写成自然语言“错题本”留在记忆里，指导下一轮尝试。
R5 - Toolformer 怎样学会什么时候该调用工具？用少量示例让模型在语料中采样调用，执行后按后续文本的预测损失筛选，再做微调。
R4 - Reasoning via Planning (RAP) 没法在真实环境里反复试错，怎么办？让大模型同时扮演“推理者”与“内部世界模型”，在脑海中用树搜索推演未来状态与长远回报。
R3 - Language Agent Tree Search (LATS) 一条检索轨迹走偏了，其他尝试还能留着吗？把蒙特卡洛树搜索、模型价值评估和语言反思结合起来，比较多个候选分支。
R19 - MetaGPT 几个角色一起写软件，怎样避免接口各说各话？沿绘图应用追踪五角色的结构化交付、共享消息池与执行反馈，再看单元测试能修好什么、不能保证什么。
R61 - Evolving Orchestration 多智能体协作一定要走完固定流程吗？中央编排器按当前状态选择下一位角色或结束任务，再用质量与成本回报训练路由，比较动态协作的收益与弱模型下的退步。
R18 - Voyager 会说铁镐配方，为什么还不能从空背包做出来？在 Minecraft 中按现场状态自动选任务，照着反馈修改执行程序，再把成功技能存成可检索、可组合的代码。
R68 - Cradle 不用软件内部 API，只看屏幕、操作键鼠，怎样完成长任务？将截图取证、反思与双记忆接到技能代码，再检查实时控制与场景适配的边界。

02 / EVALUATION

一次成功之外，怎样检验真实交互中的表现？

5 篇精读

τ-bench 与 τ²-bench 检验业务规则和双控制协作，MCP-Bench 追踪真实工具生态中的跨服务器依赖，Agent-as-a-Judge 主动读取工程产物核查交付；再用可靠性研究检查重复运行与条件变化下的表现。记忆、角色与社交的专项评测留在对应主题，与被检验的方法一起读。

R6 - τ-bench 能聊天的客服未必守得住业务红线——让智能体在多轮用户对话、数据库读写与复杂行业规则之间周旋，用 pass^k 看看多次运行是否一致。
R7 - τ²-bench 用户不只提问，还得亲手操作手机配合排障，智能体该怎么引导、怎么同步状态？用“双控制”环境找出多轮协作卡在哪里。
R67 - MCP-Bench 工具调用都成功，露营方案为什么仍不可用？沿营地、地图与天气的跨服务器依赖，拆解多轮执行、规则与裁判评分，以及综合分和调用量的边界。
R72 - Agent-as-a-Judge 只读最终回答，能判断代码工程是否真的做完吗？让裁判主动检索工作区、读取产物与运行轨迹，再按硬要求及其前置依赖逐项核查计分。
R8 - Science of AI Agent Reliability 为什么平均准确率涨了，智能体到了关键生产场景还是让人不放心？不只看一个均值，从一致性、鲁棒性、可预测性与安全性四个角度看看可靠性。

03 / MEMORY

怎样存下经历，并在需要时找回？

10 篇精读

先从 LongMemEval 与 PersonaMem 建立长期记忆与个性化回应的评估基准；接着读 HippoRAG 与 Zep，看类脑图谱与双时态知识图谱如何处理多跳关联与事实演变；再看 Mem0 与 SimpleMem 的轻量工程记忆层，以及 A-MEM 的自组织卡片盒与 ReasoningBank 的推理经验沉淀；最后进入 MEM1 的端到端状态压缩与 Memory-R1 的强化学习记忆管理。

R16 - LongMemEval 当对话跨越数百场会话，记忆系统到底卡在“没存好”、“没找准”还是“没读懂”？用五大核心记忆能力评测，看看建库、检索与阅读各环节的得失。
R17 - Know Me, Respond to Me (PersonaMem) 能背出用户的历史设定，就等于懂用户吗？在偏好看起来随时间变化的长期交互里，分清“认出用户画像”与“给出真正贴合当下处境的回应”。
R12 - HippoRAG 两个证据段落都在库里，怎么还会漏掉一段？离线抽取关系并建立图索引，查询时用个性化 PageRank 传播查询信号，再汇总成段落分数。
R13 - Zep 用户的现实情况变了，旧记忆该怎么处理？把情节、语义与社区放进三层动态图谱，再用双时态时间轴（T 与 T′）追踪事实的生效与失效。
R59 - Mem0 跨会话时怎样只记有用事实，而不重读全史？从消息对增量提取候选，与相似旧记忆比对并执行增删改；再用图版本保留关系变化，对照 LOCOMO 上的质量、延迟与 token 账本。
R83 - SimpleMem 长期对话里闲聊与指代混杂，普通摘要又会压丢细节。写入时同步过滤噪声、消解指代、锚定绝对时间并建语义、词法与元数据三路索引；提问时按意图并行召回并去重。
R14 - A-MEM 新经历来了，旧经历往往也有了新的意义——借鉴卢曼“卡片盒笔记法”，让新记忆入库时自主连接相关旧卡片，并反过来更新旧卡片的语境描述。
R60 - ReasoningBank 保存旧轨迹，为什么还会重犯旧错？从自判成功与失败的经历中提炼策略，供新任务检索；再用 MATTS 比较多路尝试或顺序复查，让更多计算也改善后续记忆。
R77 - MEM1 多轮检索每步都在追加旧网页，上下文越滚越长怎么办？用同一策略把记忆浓缩融进推理状态、每轮清理旧上下文，再借轨迹拼接与二维掩码完成 PPO 端到端训练。
R56 - Memory-R1 有记忆库为何还会答错？Memory Manager 先学习增删改或保留四类写库操作，Answer Agent 再从召回条目中筛选有效证据并作答；两者分别用最终答案的精确匹配奖励以 RL 训练。

04 / CONTEXT

怎样让长历史与经验进入下一次决策？

2 篇精读

MemGPT 解决有限窗口里保留什么、何时从外存调入或调出；ACE 解决任务反馈怎样变成可增量维护的行为手册。两篇分别管理输入容量与经验内容，重点看每次调用实际送给模型的上下文怎样变化。ReasoningBank 放在记忆组，可与 ACE 对照策略如何提炼、检索与更新。

R11 - MemGPT 历史超过窗口后，怎样留下关键事实并找回旧事？借鉴虚拟内存，让模型用函数调用来管理当前工作区、对话历史和归档存储。
R15 - ACE 一次失败怎样变成下一次可用的经验？让执行、反思与策展各管一件事，只对行为手册做增量更新，保住具体策略，再看看反馈质量与持续适应的真实代价。

05 / WORLD MODELS

学会预测动作后果，怎样帮助行动与交互？

2 篇精读

先读 DreamerV3：从真实经验学习世界模型，在想象中训练策略，再回到环境行动；再读 Genie：从视频学习潜在动作，生成可交互环境。与推理组的 RAP 对照，区分语言模型内推演、学习得到的环境动力学与真实观测，避免把想象成功当成真实成功。

R51 - DreamerV3 空背包怎样走到钻石？沿 Minecraft 案例拆开世界模型、想象轨迹与 Actor–Critic 学习，再核对跨领域固定配方，以及“曾找到钻石”与单局成功率的区别。
R52 - Genie 只看角色移动、不知道玩家按键，怎样学出可操作的世界？沿平台跳跃案例拆开动作瓶颈、视频 tokenizer 与动力学模型，再用 CoinRun 检查动作能否迁移。

06 / SOCIAL SIMULATION & ROLEPLAY

如何扮演角色、与他人协商，并从互动中学习？

7 篇精读

从 Generative Agents 的小镇生活与 Agentopia 的长期多智能体社会模拟建立整体图景；再用 SOTOPIA 确立多维社交能力评估基准，沿着 SOTOPIA-π 与 SOTOPIA-Ω 看交互自举与动态策略优化；最后以 CharacterBench 与 LLM Generated Persona 检验角色扮演深度与群体代表性的局限。

R10 - Generative Agents 怎样让智能体过上真实可信的日常，而不是机械复读角色设定？用记忆流记下经历、用定期反思提炼高阶洞见、用层级规划安排小镇社交。
R21 - Agentopia 一次体育馆偶遇，怎样走到第六周的协作？沿周循环与私有记忆拆开长期社会模拟，再看年度奖励如何筛选相对自身进步的轨迹用于离线微调，以及社交收益背后的生活代价。
R20 - SOTOPIA 聊得自然，就能在社交中达成目标吗？从借毯子失败出发，看两个角色在私有目标与信息限制下互动，再用七个维度分开评估目标、关系与行为代价。
R57 - SOTOPIA-π 小模型怎样学会协商，而不只礼貌接话？先模仿专家，再筛选自身互动中的高分角色轨迹做离线微调；对照人工评价，检查自动目标评分是否虚高。
R58 - SOTOPIA-Ω 专家也会陷入客气却无进展的僵局。按当前进展与未来预期切换原生回应、换位提示和四步协商，在数据生成时改善策略，再检查目标收益、表达多样性与人工评分差距。
R22 - CharacterBench 只靠闲聊，怎么发现角色忘记旧事、越过知识边界？围绕设定与历史构造针对性追问，用 CharacterJudge 判分，再核对评分与人类的一致性，以及用于训练的收益。
R55 - LLM Generated Persona 人物档案写得像真人，组成的人群就能代表现实吗？分开检验档案生成与回答模拟，对照选举和问卷数据，看更多细节为什么反而可能带来更大偏移。

07 / POST-TRAINING

模型如何通过后训练学会指令与偏好？

9 篇精读

先从 GAE 与 PPO 建立强化学习的优势估计和裁剪策略优化基础；再看 InstructGPT、Self-Instruct、WizardLM、LIMA 与 FireAct 如何确立 RLHF 范式、推动指令数据合成演化并拓展到智能体微调；最后读 DPO 与 KTO，理解无需显式奖励模型或配对偏好的直接偏好优化路线。

R36 - GAE 单步 TD 偏差大，蒙特卡洛回报方差高。用 λ 对多步 TD 残差做指数加权求和，成为 PPO 等现代策略梯度方法估算优势函数的标准组件。
R84 - PPO 普通策略梯度每批样本只能更新一次，TRPO 的二阶约束又太重。PPO 用裁剪概率比的悲观代理目标，只靠一阶优化就能对同一批数据做多轮更新。
R85 - InstructGPT 语言模型只会续写不会听话。通过 SFT、人类排序训练奖励模型和 PPO 强化学习三阶段 RLHF，让 1.3B 模型在人工偏好上胜过 175B GPT-3。
R86 - Self-Instruct 人工写指令既贵又慢。从 175 条种子出发让模型自己生成指令、输入输出并去重过滤，用 52k 合成数据做出接近 InstructGPT 的指令跟随能力。
R88 - WizardLM 人工标注和自举数据普遍偏简单。用 Evol-Instruct 对指令做深度加难与广度变异并过滤失败样本，以 70k 数据让 LLaMA-13B 超越 Alpaca 与 Vicuna。
R87 - LIMA 知识主要留在预训练里，微调只在教回答格式与风格。仅用 1,000 条高质量多样示范做 SFT，就在盲测中追平甚至胜过 52k 数据与部分 RLHF 基线。
R25 - FireAct 少样本提示下的智能体既贵又容易卡死。混合 CoT、ReAct 与 Reflexion 的成功轨迹微调小模型，在 HotpotQA 上大幅提分并降低推理开销。
R27 - DPO 把 RLHF 奖励模型与最优策略的闭式关系代回 Bradley–Terry 目标，省去奖励模型和在线采样，只用二元交叉熵损失就能从成对偏好直接对齐。
R89 - KTO 线上反馈多是单条赞踩而非成对比较。KTO 用微批次错位估计的 KL 基准替代配对负样本，放进 S 型效用函数优化，在 1B 至 30B 规模追平或胜过 DPO。

08 / ENGINEERING

多步模型程序，怎样执行得更高效？

1 篇精读

智能体的多步生成与并行分支，最终都要落到推理服务上执行。从 SGLang 入手，追踪程序结构如何暴露共享前缀与并行机会，再看缓存复用、格式约束解码与调度怎样改变吞吐和延迟。

R50 - SGLang 多步生成与并行分支为什么重复计算共享前缀？从前端程序到 RadixAttention、缓存调度与约束解码，追踪结构化模型程序的执行开销。
